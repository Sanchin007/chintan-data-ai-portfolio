01 / OPERATING MODEL

Before and after: how the work changes

A process-design comparison showing where orchestration adds consistency and traceability. It is not a measured productivity claim.

PROCESS MAPPING
BASELINE · MANUAL / FRAGMENTED

Analyst-led sequence

  1. Receive an audit question through email or a meeting
  2. Collect spreadsheets and source extracts from multiple owners
  3. Manually identify the relevant records and control tests
  4. Reconcile data and calculate exceptions in separate files
  5. Ask domain specialists to validate context and policy
  6. Assemble findings, references and a report manually
Typical friction: repeated hand-offs, inconsistent test execution, fragmented evidence and limited end-to-end traceability.
→
AGENT-ASSISTED · THIS DEMONSTRATOR

Orchestrated, evidence-led sequence

  1. Describe the objective in natural language
  2. Gemini interprets scope and checks dataset readiness
  3. Model selects only the relevant allow-listed tools
  4. Deterministic tests return reproducible outputs and record IDs
  5. Evidence challenger surfaces gaps and alternative explanations
  6. Specialists review flagged items; a draft workpaper is generated
Designed improvement: consistent execution, visible tool traces, linked evidence and explicit human decision points.
What does not change: accountable auditors and specialists still own interpretation, legal or policy conclusions, finding acceptance, remediation and consequential decisions. The agent accelerates analysis preparation; it does not replace professional judgement.

EXPORT / TRADE-COMPLIANCE ROUTE

Agent flags incomplete classification, authorisation, end-user / end-use or party-screening evidence → review queue assigns the item to a trade-compliance specialist → specialist checks current law, official sources and transaction facts → authorised human records the disposition. The agent never declares a shipment legally cleared.

SPECIALIST VERIFICATION REQUIRED
Decision contract: tool result + source record IDs + test parameters + evidence gaps + alternative explanations + reviewer identity + human decision. The demo captures a draft review state in the browser session; it does not persist an enterprise audit log.

05 / TOOLING CONTRACT

Tool catalogue: what the model can actually call

The model may select from these functions. Each function has a bounded schema and deterministic implementation; the model does not execute arbitrary SQL or code.

11 ALLOW-LISTED FUNCTIONS
DATA / DISCOVERYprofile_demo_dataset

Returns available synthetic datasets, row counts and fields.

Input: dataset scope · Output: schema profile
DATA / QUALITYrun_data_quality_assessment

Checks blank cells and exact duplicate rows before analysis.

Input: dataset scope · Output: PASS / REVIEW
GOVERNANCE / COVERAGErun_control_coverage_assessment

Shows implemented checks and explicitly unavailable capabilities.

Input: domain scope · Output: coverage catalogue
FINANCErun_invoice_duplicate_test

Matches supplier, amount, PO and currency within a bounded date window; checks payment evidence fields.

Input: window_days · Output: duplicate candidates
PROCUREMENTrun_procurement_threshold_test

Finds clustered purchase orders below an illustrative approval threshold.

Input: threshold and date window · Output: cluster indicators
SUPPLIER GOVERNANCErun_supplier_change_test

Checks supplier-master change timing, payment value, callback and dual-approval evidence.

Input: value threshold and lookback · Output: control candidates
COMMERCIALrun_pricing_variance_test

Calculates contribution margin and compares discounts with a synthetic approval reference.

Input: material discount gap · Output: variance candidates
OPERATIONSrun_fleet_utilisation_test

Compares asset utilisation with cohort benchmark and unit-cost context.

Input: minimum benchmark gap · Output: outlier candidates
TRADE / DOCUMENTATIONrun_export_documentation_triage

Flags missing or unverified classification, authorisation, end-user / end-use and party-screening evidence.

Input: evidence category · Output: specialist review flags
ASSURANCEchallenge_evidence

Surfaces alternative explanations, evidence gaps and corroboration steps for a finding.

Input: finding and evidence IDs · Output: challenge questions
REPORTINGdraft_workpaper

Creates a draft only from tool-returned findings that have passed the evidence-challenge step.

Input: title, scope, finding IDs and review notes · Output: draft pending human review
Explicit exclusions: no unrestricted database query, arbitrary code execution, live ERP / BigQuery connection, live sanctions or restricted-party screening, legal licence determination, payment operation, approval or write-back.
